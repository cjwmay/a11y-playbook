Day 2 · 大字与非文本对比度 3:1Large text & non-text contrast 3:1 — borders and icons can't be too light either

WCAG 1.4.3 Contrast (Minimum) 大字豁免 + 1.4.11 Non-text Contrast · AA

📏 规则一句话The rule in one sentence

中文
对比度不是一刀切 4.5:1：大字（≥24px，或 ≥18.66px 加粗）文本只要 3:1；但 UI 里的关键非文本图形——输入框边框、图标、图表线条、开关状态——也要和它紧贴的颜色达到 3:1。纯装饰和 disabled 状态豁免。
ENGLISH
Contrast isn't a flat 4.5:1: large text (≥24px, or ≥18.66px bold) only needs 3:1; but essential non-text graphics — input borders, icons, chart lines, toggle states — also need 3:1 against their adjacent colors. Pure decoration and disabled states are exempt.

⚠️ 避坑Pitfalls

中文
  • 1.4.11 比的是图形 vs 它紧贴的颜色（图标 vs 背景、开关圆钮 vs 轨道），不是 vs 页面背景。
  • disabled / 置灰控件豁免——但别拿豁免当借口把禁用态做成隐形，用户还是要能"看见它存在"。
  • Logo 豁免，品牌色不用改。
  • 很多设计系统只给文本设了对比度 token，边框/图标色是裸色号 —— 这就是 1.4.11 最常见的坑。
ENGLISH
  • 1.4.11 compares the graphic against its adjacent color (icon vs background, knob vs track), not the page background.
  • Disabled controls are exempt — but don't use that as an excuse to make them invisible; users still need to perceive they exist.
  • Logos are exempt — brand colors stay.
  • Many design systems tokenize text contrast but leave border/icon colors as raw hex — that's the most common 1.4.11 trap.

🔍 怎么测How to test

中文
  1. Chrome DevTools：选中元素 → Styles 里点 border-color / 图标 color 的色块 → 取色器直接显示比值。
  2. axe DevTools / WAVE：自动标出 1.4.11 不达标的非文本元素。
  3. Figma：Stark 插件的 non-text 对比度检查，一键扫全画面的图标和描边。
  4. 在线：WebAIM Contrast Checker，任意两色号都能算。
ENGLISH
  1. Chrome DevTools: select the element → click the border-color / icon color swatch in Styles → the picker shows the ratio.
  2. axe DevTools / WAVE: flags non-text elements failing 1.4.11 automatically.
  3. Figma: Stark's non-text contrast check scans icons and strokes across the frame.
  4. Online: WebAIM Contrast Checker — any two hex values.

🛠️ 一行修复The one-line fix

/* 输入框描边：1.48:1 → 3.03:1 / input border: 1.48:1 → 3.03:1 */
border-color: #cbd5e1; border-color: #949494; /* 想更保险用 #767676 (4.54:1) / safer: #767676 */

✏️ 练习Exercise

中文
  1. 打开你最近一张设计稿，数一数有几个图标 / 描边色浅于 #949494。
  2. 把你设计系统的 border token 全部跑一遍 WebAIM，列出挂掉的。
  3. 找一个开关组件：开态色 vs 背景够 3:1 吗？开态 vs 关态能区分吗？
ENGLISH
  1. Open your latest mock: count icons / strokes lighter than #949494.
  2. Run every border token in your design system through WebAIM; list the failures.
  3. Find a toggle: does the on-state color hit 3:1 vs background? Can you tell on from off?
🎙️ 面试怎么讲："对比度我不是一刀切 4.5:1 —— 正文小字 4.5:1，大字和关键非文本图形 3:1 就够，装饰和 disabled 豁免。上次我把输入框描边 token 从 #CBD5E1 提到 #767676，因为 1.48:1 的框线低视力用户根本看不见 —— 这是 WCAG 1.4.11，也是设计稿最容易挂的地方。"
🎙️ Interview line: "I don't apply 4.5:1 blindly — body text gets 4.5:1, large text and essential non-text graphics get 3:1, decoration and disabled are exempt. I once raised our input-border token from #CBD5E1 to #767676 because at 1.48:1 low-vision users couldn't even see the box — that's WCAG 1.4.11, and it's where most mockups fail."
